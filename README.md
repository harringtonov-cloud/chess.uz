# chess.uz

Шахматный сайт: React + Vite + TypeScript, база и вход — Firebase (Auth + Firestore), хостинг — Vercel.

## Что уже есть

- **Онлайн-партии 1 на 1** в реальном времени: быстрый подбор соперника, игра по ссылке, часы (пуля, блиц, рапид, классика), ничья, сдача, отмена, реванш, чат, смайлы
- **Своя игра**: вы сами задаёте минуты на партию (от 15 секунд до 3 часов), добавку за ход, цвет, рейтинговая или нет, открытая или только по ссылке; список открытых партий, которые можно принять одним нажатием
- **Смотреть партии**: список идущих публичных партий (первая — самая сильная), просмотр в реальном времени
- **Ежедневные партии**: от 1 до 14 суток на ход, можно закрыть сайт и вернуться; список «Мои ежедневные партии» с пометкой «Ваш ход» и счётчиком в меню; просрочка хода = поражение; без рейтинга
- **Редактор позиции**: расстановка фигур, ход и рокировки, FEN, отправка в анализ или игра с ботом из позиции
- **Друзья и клубы**: запросы в друзья, личные сообщения, приглашения на партию; клубы (открытые и по заявке), роли, чат клуба, вызов участника на партию
- **Турниры** по швейцарской системе: регистрация, жеребьёвка туров, результаты из партий, таблица (очки, бухгольц)
- **Арена-турниры**: играйте сколько хотите за отведённое время (от 10 минут до 3 часов), после каждой партии вас сразу ставят в пару; победа — 2 очка, ничья — 1, серия из двух побед удваивает очки 🔥; таблица в реальном времени
- **Форум**: темы и ответы, защита от спама (пауза между сообщениями), мьют закрывает форум, сотрудники удаляют сообщения с записью в журнал
- **Уведомления**: колокольчик в меню и страница /notifications; запросы в друзья, сообщения, приглашения, «ваш ход» в ежедневных партиях, заявки и приём в клуб, новый тур турнира; настройки по типам, звук, всплывающие окна браузера; чёрный список (кнопка на странице профиля)
- **Настройки**: темы доски, наборы фигур, координаты
- **Рейтинг Эло** по контролям времени, профили, таблица лидеров, история партий
- **Игра с ботами** (7 уровней, Stockfish в браузере): подсказка, отмена хода, выбор цвета, шахматные часы (1+0 … 15+10), фора боту (без пешки, коня, ладьи, ферзя), старт из своей позиции (FEN)
- **Анализ партий**: Stockfish, график преимущества, оценка каждого хода (неточность / ошибка / грубая ошибка), точность в %, импорт PGN и FEN
- **Головоломки** из базы Lichess с рейтингом, сериями и подсказками (есть запасные задачи на случай, если база недоступна)
- **Учиться**: 5 интерактивных уроков (как ходят фигуры, шах/мат/пат, особые ходы, основы тактики, принципы дебюта) с заданиями на доске; прогресс хранится в браузере
- **Дебютный справочник**: 86 дебютных систем и вариантов, названия по ходам, поиск по названию, известные продолжения (без статистики побед)
- **Puzzle Rush**: задачи на скорость, 3 или 5 минут, три ошибки заканчивают забег, личный рекорд
- **Шахматное зрение**: тренажёр — найти поле по названию на пустой доске за 30 секунд
- **Задача дня** из базы Lichess
- **Профиль**: график рейтинга, статистика по цветам, 11 достижений
- **Стрелки и пометки на доске**: правая кнопка мыши (протянуть — стрелка, клик — подсветка поля)
- Правила: рокировка, взятие на проходе, превращение, мат/пат/ничья (повторение, 50 ходов, недостаток материала)

## Запуск локально

```bash
npm install
cp .env.example .env.local   # впишите ключи Firebase
npm run dev
```

Без ключей Firebase работают боты, анализ и головоломки; онлайн-игра и профили будут отключены.

## Настройка Firebase

1. [console.firebase.google.com](https://console.firebase.google.com) → **Add project**.
2. **Build → Authentication → Sign-in method**: включите **Google** и **Email/Password**.
3. **Authentication → Settings → Authorized domains**: добавьте домен вашего сайта на Vercel и свой домен (chess.uz).
4. **Build → Firestore Database → Create database** (режим production, ближайший регион).
5. **Project settings → Your apps → Web app (`</>`)**: скопируйте конфиг в `.env.local` (поля `VITE_FIREBASE_*`).
6. Опубликуйте правила и индексы:
   ```bash
   npm i -g firebase-tools
   firebase login
   firebase use --add          # выберите проект
   firebase deploy --only firestore
   ```
   Это загрузит `firestore.rules` и `firestore.indexes.json` (индекс нужен для истории партий в профиле).

## Деплой на Vercel

1. **Add New → Project** → выберите репозиторий. Vercel сам определит Vite (build: `npm run build`, output: `dist`); маршрутизация SPA настроена в `vercel.json`.
2. Конфиг Firebase уже зашит в `src/firebase.ts` как значения по умолчанию. Чтобы использовать другой проект Firebase, задайте `VITE_FIREBASE_*` в Project Settings → Environment Variables.
3. После первого деплоя добавьте домен Vercel (`*.vercel.app`) и свой домен (chess.uz) в Firebase → Authentication → Settings → **Authorized domains**, иначе вход через Google не сработает.

## Индекс Firestore (по желанию)

Профиль игрока и список ваших ежедневных партий запрашивают «партии игрока, новые сверху», что в Firestore требует составной индекс (он описан в `firestore.indexes.json`). Сайт работает и без него: если индекса нет, партии читаются без сортировки и сортируются в браузере (до 300 штук). Чтобы запросы были быстрее и дешевле, создайте индекс: `firebase deploy --only firestore:indexes` либо Firebase Console → Firestore → Indexes → Add index: коллекция `games`, поля `participants` (Array contains) и `createdAt` (Descending).

## Известные ограничения (важно)

- Правильность ходов, часы и обновление рейтинга проверяются **в браузерах игроков**. Правила Firestore пускают в партию только её участников, но без серверного кода (Cloud Functions) нельзя полностью исключить жульничество. Для серьёзного запуска перенесите `makeMove`, `flagGame` и `applyRating` в Cloud Functions.
- Брошенные ожидающие партии остаются в базе (подбор их игнорирует по «пульсу» создателя). Их можно чистить по расписанию Cloud Function.
- Фигуры рисуются символами Unicode; для своего вида подключите набор SVG-фигур.
- Движок Stockfish (asm.js) подгружается с CDN jsDelivr.

## После обновления правил

В `firestore.rules` добавлена проверка времени при создании партии (от 10 секунд до 4 часов, добавка до 5 минут; для ежедневных партий — от 1 до 14 суток на ход). Опубликуйте правила заново: Firebase Console → Firestore → Rules → Publish (или `firebase deploy --only firestore:rules`). Пока правила не обновлены, своя игра работает, но серверной проверки границ нет.

## Уведомления: что сделать после обновления

1. Заново опубликуйте `firestore.rules` (Firebase Console → Firestore → Rules → Publish). Без этого уведомления и чёрный список не заработают: правила для них новые.
2. По желанию включите автоудаление старых уведомлений: Firebase Console → Firestore → TTL → создайте политику для группы коллекций `notifications` по полю `createdAt` (например, чтобы записи старше 30 дней удалялись сами). Эта настройка не обязательна.

Как это устроено: уведомление — документ в `users/{uid}/notifications`. Его создаёт отправитель события (без серверного кода), а читает и удаляет только получатель. Одно и то же событие от одного игрока заменяет прежнее уведомление, поэтому десять сообщений подряд дают одну запись. Настройки типов, звука и окон браузера хранятся в браузере игрока. Уведомления приходят, пока сайт открыт; настоящие push-сообщения на закрытый телефон появятся вместе с мобильным приложением.

## Админ-панель и жалобы: что сделать после обновления

1. Заново опубликуйте `firestore.rules` (Firebase Console → Firestore → Rules → Publish). Без этого жалобы, санкции и панель не заработают.
2. **Владелец сайта** (uid записан в `firestore.rules` и в `src/lib/moderationLogic.ts`, константа `OWNER_UID`) автоматически администратор: заходить в Firebase и создавать записи не нужно. Он же назначает и снимает других сотрудников во вкладке «👑 Сотрудники» панели (по нику или по uid). Чтобы сменить владельца, замените uid в этих двух местах.
3. В верхнем меню появится значок 🛡 (страница `/admin`).

Что есть:

- **Жалобы.** Кнопка «🚩 Пожаловаться» на профиле игрока и под чатом в партии (причины: читерство, оскорбления, спам, ник, затягивание, накрутка рейтинга, другое). Одна жалоба на игрока по профилю и по одной на каждую партию.
- **Панель.** Обзор со счётчиками, очередь жалоб с фильтрами и списком «на кого жалуются чаще», карточка игрока (партии, жалобы на него и от него), санкции, журнал действий, объявление сайта.
- **Санкции.** Предупреждение, мьют (чаты) и бан (нельзя создавать и принимать партии, клубы, турниры, приглашения) на 1 час, 1 день, 7 дней, 30 дней или навсегда. Модератор может до 30 дней, навсегда только администратор. Игрок получает уведомление и видит красную полосу с причиной и сроком; по истечении срока ограничение снимается само.
- **Только администратор.** Сброс рейтингов, очистка ника и описания, публикация объявления сайта.
- **Чат.** Сотрудники видят кнопку ✕ у каждого сообщения в чате партии и клуба (удаление попадает в журнал).
- Каждое действие записывается в журнал `modLog`; изменить или удалить запись нельзя.

Ограничения: бан не прерывает уже начатую партию (серверного кода нет, это тоже закроют Cloud Functions), а проверку читов движком ещё предстоит сделать отдельным блоком. Бан по IP и по устройству невозможен без сервера.

## Арена-турниры: что сделать после обновления

Заново опубликуйте `firestore.rules` (Firebase Console → Firestore → Rules → Publish): без этого арены не заработают. Создаётся арена на странице «Турниры» (вид турнира → «Арена»).

Как это устроено: арена — обычный документ турнира с `type: 'arena'`, временем начала и конца (`startsAt`, `endsAt`). Игроки лежат в `players`, итоги партий — в `results`. Серверного кода нет, поэтому пары подбирают браузеры игроков: пока страница арены открыта, клиент раз в 3 секунды ищет ближайшего по рейтингу свободного соперника (не из двух последних), а партию создаёт транзакция, которая заново проверяет, что оба свободны. Результат партии записывает сам игрок, а правила Firestore сверяют его с закончившейся партией. Игрок, закрывший страницу арены, через 30 секунд выпадает из подбора.

Ограничения те же, что у остального сайта: без Cloud Functions нельзя полностью исключить жульничество с результатами.
## Форум: что сделать после обновления

Заново опубликуйте `firestore.rules` (Firebase Console → Firestore → Rules → Publish): без этого форум не заработает. Страница `/forum` появится в меню.

Автор удаляет свою тему или ответ; сотрудники модерации удаляют любые, вместе с ответами темы, и действие попадает в журнал. Если автор удалил свою тему, её ответы остаются в базе, но нигде не показываются (чистить их можно по расписанию Cloud Function).
